# Android 设备人工验收

> 本清单只记录当前自动化测试无法稳定覆盖的 Android 系统 UI 与设备交互。
> 自动化基线见 [BASELINE.md](BASELINE.md)。

## 适用场景

以下流程应使用真实设备或可交互模拟器人工执行：

- SAF 目录选择器、持久化授权与权限撤销；
- Android 13+ 通知运行时权限及系统设置中的权限变化；
- Android 17 / targetSdk 37 的本地网络权限；
- 外部分享、Share Inbox 与深链冷/热启动。

这些路径依赖系统弹窗、系统选择器或外部应用的交互结果，暂不作为 CI 自动化门禁。

## 测试前准备

1. 使用 `tools\agent.cmd build-android --install` 安装当前 debug 包。
2. 清理应用数据，确认从首次启动状态开始。
3. 记录设备型号、Android 版本、API level、ABI 和测试日期。
4. 如需重复测试通知权限，在系统应用设置中撤销通知权限，或清理应用数据后重装。

## SAF 下载目录

### 选择自定义目录

1. 打开“设置 → 下载目录”，选择“自定义目录”并启动系统目录选择器。
2. 选择一个非公共 Downloads 的目录，例如 Documents 下的新目录。
3. 确认应用显示正确的目录 URI/展示名称，且没有请求存储管理权限。
4. 下载一个测试文件，确认文件实际出现在所选目录。
5. 重启应用后再次下载，确认授权仍然有效。

### 撤销授权

1. 在系统设置中撤销该目录的持久化权限，或删除对应目录授权。
2. 回到应用再次下载到同一目录。
3. 确认应用给出可理解的权限失效提示，不崩溃、不误报成功。
4. 重新选择目录后，下载恢复。

### 默认 Downloads

1. 将下载目录切回默认公共 Downloads。
2. 下载文件并确认出现在 `Download/LanCloud`。
3. 确认文件可从传输中心打开、分享和删除。

MediaStore 写入与 content URI 删除已有自动化 smoke；本项只验收系统 UI 与文件可见性。

## 通知运行时权限

在 Android 13+ 上分别执行拒绝和允许路径。

### 拒绝

1. 清理应用数据，打开设置中的进度通知开关。
2. 系统通知权限弹窗出现时选择拒绝。
3. 确认应用不崩溃，开关状态或权限提示与实际系统状态一致。
4. 发起传输，确认传输本身不受影响，但没有进度通知。

### 允许

1. 在系统设置中开启通知，或在应用内重新触发授权。
2. 发起下载和上传，确认进度通知显示并持续更新。
3. 覆盖完成、失败和暂停状态。
4. 点击完成通知，确认进入对应传输页或文件动作。
5. 在系统设置撤销通知权限后回到应用，确认状态刷新且无错误。

## Android 17 本地网络权限

1. 使用 Android 17 / targetSdk 37 设备或模拟器清理应用数据。
2. 首次访问网盘接口或分享链接。
3. 确认系统显示本地网络访问权限。
4. 分别验证允许、拒绝以及从系统设置重新授权后的网络行为。
5. 确认拒绝时有明确提示，且不会无限重试或吞掉错误。

## 深链与 Share Inbox

### 冷启动深链

1. 完全结束应用进程。
2. 从浏览器或消息应用打开 LanCloud 支持的分享链接。
3. 选择由 LanCloud 打开。
4. 确认冷启动后直接进入分享解析流程，而不是停留在普通首页。

### 热启动深链

1. 保持应用在后台。
2. 从外部应用再次打开分享链接。
3. 确认回到前台并只处理一次链接。

### Share Inbox

1. 从浏览器、文件管理器分别分享文本链接和文件到 LanCloud。
2. 确认文本进入分享链接流程，文件进入上传或待上传流程。
3. 确认取消外部分享、无内容分享和重复分享不会造成重复任务或崩溃。
